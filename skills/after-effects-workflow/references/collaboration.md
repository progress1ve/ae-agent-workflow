# Working with an artist

## Start with concrete constraints

Record duration, fps, canvas size, copy, logo, palette, original assets, voice, sound pack, safe edges, alpha/chroma needs and review mode. A useful brief says what each scene must communicate. A reference should be decomposed into typography, layout, depth, lighting, timing and camera behavior; do not copy its brand.

## Revision loop

Prefer a screenshot annotation plus timestamp: “at3.8s, enlarge the phone; show the entire top rim; crop the bottom.” Check both endpoints of a transition. When changing a brand lockup, center the combined visible icon and text bounds—not only the text layer anchor. Keep the approved timing unless the user changes it.

Different scenes need different visual roles. A price/product scene can use a directional light; a contact scene can use a quiet halo and large handle. Decorative icons should support depth with restrained opacity/blur, not compete with the message. Preserve their visual identity.

Ask the user to review the named composition at specific times. Do not repeatedly render the entire video during small edits. If they request minimal communication, use one short action update, meaningful findings when needed, and a concise final with artifact links.

## Durable handoff

Store this next to the media project rather than in a unrelated code repository:

```text
Current AEP / review composition:
Canvas / duration / fps:
Approved copy and scene timing:
Latest asset paths / font requirements:
Voice and SFX plan:
Changed and verified:
Pending user feedback:
Export authorized? Which revision?
Retained versions and dependency locations:
```

MCP does not confer permission for destructive cleanup, posting messages, publishing, paid generation or changing unrelated settings. Continue within the user's authorized scope; do not add approval questions for ordinary reversible editing.
